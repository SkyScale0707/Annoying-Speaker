## 3. 同项目参考：`elytra-music`（1.21.1）已验证的做法

路径：`E:\MCProject\elytra-music\elytra-music-template-1.21.1`

它解决过**同一个问题**——从磁盘目录播放 OGG，而不是从资源包。可复用的是 3 个部件：

| 部件 | 文件 | 关键点 |
|---|---|---|
| 让引擎「认」这个声音 | `client/mixin/ElytraMusicCustom/ElytraMusicSoundManagerMixin.java` | Mixin `SoundManager#get(Identifier)`：命名空间命中时返回**合成的 `WeightedSoundSet`**，塞一个 `Sound(..., RegistrationType.FILE, stream=true, preload=false, 16)` |
| 让引擎从磁盘读文件 | `.../ElytraMusicSoundLoaderMixin.java` | Mixin `SoundLoader#loadStreamed`：HEAD 处 `setReturnValue(CompletableFuture.supplyAsync(() -> new OggAudioStream(new FileInputStream(file))))` |
| 淡入淡出 | `client/ElytraMusicFadeInstance.java` | `extends AbstractSoundInstance implements TickableSoundInstance`，在 `tick()` 里**直接改 `this.volume`**，`isDone()` 用自建 `done` 标志 |

**两个踩过的坑（务必继承）**：

1. `Sound#getPath()` 会自动补 `sounds/` 前缀与 `.ogg` 后缀，磁盘查找前必须还原成裸文件名。
2. 淡入淡出**只覆写 `getVolume()` 无效**——`SoundSystem` 读的是 `this.volume` 字段，必须每 tick 写回。

配置写法参考 `src/main/java/com/ggscaletest/ElytraMusicConfig.java`：`FabricLoader.getInstance().getConfigDir()`
+ Gson 手写读写，`fadeSteps = fadeSeconds * 20`。

## 4. 26.3 对应 API（改名表，迁移时照这张表改）

> 依据：`.agent\.cache\src\client`（26.3 反编译源码），行号为该版本行号。

| elytra-music 用的（1.21.1 / yarn） | 26.3（mojmap） | 证据 |
|---|---|---|
| `net.minecraft.client.sound.SoundManager` | `net.minecraft.client.sounds.SoundManager` | `client/sounds/SoundManager.java` |
| `SoundManager#get(Identifier)` → `WeightedSoundSet` | `#getSoundEvent(Identifier)` → `@Nullable WeighedSoundEvents` | `SoundManager.java:170` |
| `WeightedSoundSet` | `WeighedSoundEvents`（注意拼写） | `client/sounds/WeighedSoundEvents.java:18`（构造 `(Identifier, @Nullable String)`）、`:60`（`addSound`） |
| `SoundLoader#loadStreamed` | `SoundBufferLibrary#getStream(Identifier, boolean looping)` | `client/sounds/SoundBufferLibrary.java:40-49`（内部 `resourceManager.open(location)`） |
| `OggAudioStream` | `JOrbisAudioStream` | `client/sounds/JOrbisAudioStream.java`（229 行） |
| `Sound.RegistrationType.FILE` | `Sound.Type.FILE` | `client/resources/sounds/Sound.java:100`（枚举还有 `SOUND_EVENT`） |
| `new Sound(id, ConstantFloatProvider…)` | `new Sound(id, ConstantFloat.of(…), ConstantFloat.of(…), 1, Sound.Type.FILE, true, false, 16)` | `Sound.java:22-40`；范例 `SoundManager.java:44` |
| `AbstractSoundInstance` / `TickableSoundInstance` | 同名，但包为 `net.minecraft.client.resources.sounds` | `AbstractSoundInstance.java:27`（`SoundEvent` 构造）、`:31`（**`Identifier` 构造**） |
| `Identifier.of(ns, path)` | `Identifier.fromNamespaceAndPath(ns, path)` | 工程内已有 `AnnoyingSpeaker.id(path)` 可复用 |
| `MinecraftClient.getInstance().runDirectory` | `Minecraft.getInstance().gameDirectory`（`public final File`） | `Minecraft.java:315` |

**结论：elytra-music 的两条 Mixin 思路在 26.3 仍然成立，但注入目标换成
`SoundManager#getSoundEvent` 与 `SoundBufferLibrary#getStream`。** 另外 26.3 的 `AbstractSoundInstance`
可直接用 `Identifier` 构造，比先造 `SoundEvent` 更省事。

## 5. 下一步（按顺序，每步都有验收）

### 阶段 A · 修骨架（半天内可完成）

1. `MusicStructure` 改成正经数据类：`record MusicStructure(String name, Path path, MusicType type)`
   （或普通类 + `final` 字段），删掉构造器里的局部变量。
2. `MusicType` 补两个映射：`displayName()`（给 lang/UI 用）与 `folderName()`（`driver_music` /
   `celestial_melody` / `normal`），用枚举构造参数承载，别在 `if/else` 里硬编码中文目录名。
3. 路径统一走 `FabricLoader.getInstance().getConfigDir().resolve("annoying_speaker/music_folder")`，
   去掉 `run\config\...` 这种带反斜杠的硬编码（专用服务端/其他启动器会失效）。
4. `MusicFolder` 实现扫描：给定目录 → `Files.list` 过滤 `.ogg`（忽略大小写）→ 产出 `MusicStructure`；
   目录不存在时创建并记日志。

**验收**：启动后日志能打印三个分类各自扫描到几首；`musicList` 内容与目录实际文件一一对应。

### 阶段 B · 让声音「存在」（先能听到，再谈控制）

1. 客户端 `ClientModInitializer` 里扫描并生成**播放 ID 表**：`annoying-speaker:<文件名>`（去掉 `.ogg`），
   与 elytra-music 的 `CUSTOM_MUSIC_IDS` 同构。
2. 新增两条客户端 Mixin（放 `src/client/java/com/ggscaletest/client/mixin/`，并登记到
   `src/client/resources/annoying-speaker.client.mixins.json`）：
   - `SoundManager#getSoundEvent(Identifier)`：命名空间 + ID 表命中 → 返回合成 `WeighedSoundEvents`
   - `SoundBufferLibrary#getStream(Identifier, boolean)`：命中 → 从磁盘 `JOrbisAudioStream`
   - 两处都要做 `sounds/` 前缀与 `.ogg` 后缀的还原（坑 1）
3. 用一个临时触发（例如右键界面里的按钮，或 `/playsound annoying-speaker:<file>`）验证能出声。

**验收**：`run/logs/latest.log` 无加载异常；能听到声音；客户端与专用服务端都不崩（服务端不加载这些类）。

### 阶段 C · 播放控制与淡入淡出

1. `SpeakerMusicInstance extends AbstractSoundInstance implements TickableSoundInstance`：
   `tick()` 里写回 `this.volume`（坑 2），提供 `startFadeOut()` / `isDone()`。
2. 一个 `SpeakerMusicController`（客户端单例）管理「当前曲目」：`play(id)` / `stop()` / `isPlaying()` /
   `next()`；切歌时先淡出再淡入。
3. 与界面联动：`SpeakerScreen` 显示当前曲名与播放状态，加「播放/停止/下一首」按钮。
   **注意**：此时仍是客户端本地行为（界面没有菜单同步），多人下其他玩家听不到。

**验收**：进出界面、切歌、停止都能正确淡入淡出；重复点击不会叠音；退出世界不残留播放实例。

### 阶段 D · 服务端驱动与多人同步（需要设计拍板，见 §6）

- 若「音响是空间音源」：在服务端对目标坐标 `level.playSound(null, pos, SoundEvent, SoundSource.RECORDS, …)`，
  前提是这些 OGG 能被**所有客户端**读到 → 要么放进资源包，要么走自定义网络包广播文件名。
- 若「只有点界面的人听」：保持客户端本地播放即可，但要明确写进文档避免以后误解。

### 阶段 E · 内容与体验

- 分类语义落地（`MusicType` 目前只是占位：司凤音乐/天籁之音/正常旋律到底影响什么？）
- 界面美化、曲目列表、音量/进度、唱片机式红石触发等
